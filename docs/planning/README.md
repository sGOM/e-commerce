# 신규 기능 기획 — 마켓컬리 벤치마킹

> 작성일: 2026-07-04 · 상태: 아래 기능은 **모두 구현됨**(2026-09-30 기준). 남은 백로그는 [../ROADMAP.md](../ROADMAP.md).
> 각 기획서의 "데이터 모델/API 개략"·"오픈 이슈"는 기획 당시 기록이다 — 실제 스키마·API 는 코드(`db/migration`, Swagger)가 원천.
> 코드 주석이 `<slug>.md §N`·`(ACn)` 으로 인용하므로 기획서의 절·AC 번호는 바꾸지 않는다.

## 배경

현재 이커머스 플랫폼은 마켓플레이스 MVP(멀티 셀러 주문, 쿠폰/포인트, 게스트 주문, 셀러 정산)까지
완료된 상태다(`PRD.md`, `README.md`, `docs/SERVER_ARCHITECTURE.md` 참고). 여기서부터는 "산다"를
넘어 "탐색·재방문·신뢰"를 강화하는 커머스 경험이 필요하다. 마켓컬리는 신선식품 새벽배송에서
출발했지만, 우리가 참고할 차별점은 배송 자체보다 **탐색·신뢰·재구매를 만드는 장치**들이다:

- 포토리뷰 중심의 구매 후기(신뢰)
- 재입고 알림(수요 놓치지 않기)
- 기획전/컬렉션 큐레이션(발견)
- 타임딜(긴급성)
- 배송 슬롯 예약(예측 가능한 배송)
- 유료 멤버십(록인)
- 선물하기(신규 유입 채널)
- 정기배송(반복 구매 자동화)

이 문서는 위 8개 기능 후보를 **우리 아키텍처(SubOrder 분리, 게스트/회원 구분, 원자적 재고 UPDATE,
정책 DB 행, 서버 금액 계산)에 맞춰** 정의한다. 이미 구현된 기능(상품검색, 인기상품, 쿠폰/포인트,
정산 등)은 재정의하지 않고 전제로 삼는다.

## 다른 서브에이전트를 위한 안내

- 이 디렉터리는 **"무엇을·왜"** 를 정의한 기획 문서다. **"어떻게 구현할지"는 각 전문 에이전트가
  결정**한다.
  - 데이터 모델·API 상세 설계·트랜잭션/동시성 전략: **spring-expert** — 각 문서의 "데이터 모델/API
    개략"은 출발점일 뿐, 실제 컬럼 타입·인덱스·마이그레이션 버전은 spring-expert가 확정한다.
  - 화면 톤/컴포넌트/접근성: **uiux-expert** — `docs/design/storefront-ui-spec.md`의 토큰·컴포넌트
    체계를 따른다.
  - 프론트 구현: **react-expert** — 각 문서의 "프론트 화면/플로우 개략"을 참고해 라우트·상태관리를
    설계한다.
- 새 기획서는 이 디렉터리의 형식(배경 → 목표 → 유저스토리·AC → 정책 → 데이터 모델/API 개략 → 화면 → 범위 → 오픈 이슈)을 따르고,
  구현 방향이 갈리는 오픈 이슈는 착수 전 프로덕트 오너와 확정한다.

## 공통 오픈 이슈 (여러 기능에 걸침)

1. **정기결제(빌링) 인프라 부재**: 멤버십·정기배송 모두 카드 빌링키 발급/저장/재시도가 필요하다.
   토스페이먼츠 빌링 API 연동 여부와 시점을 먼저 결정해야 한다.
   > 부분 해소: 공통 `billing` 골격(빌링키·청구·재시도)은 구현, 게이트웨이는 `billing.gateway=mock` 만 있다(실 PG 빌링 미연동).
2. **배송비 모델 부재**: 현재 PRD/구현에 배송비(shipping fee) 개념이 없어 보인다(무료배송으로
   추정). 멤버십의 "무료배송 혜택", 배송 슬롯의 "새벽배송 추가요금" 등을 기획하려면 배송비 모델
   확정이 선행되어야 한다.
   > ✅ 2026-09-25 확정·구현: 판매자(SubOrder)당 기본 배송비 3,000원(`shipping_policies` 정책 행) + 슬롯 추가요금, 멤버십 무료배송이면 0원(ROADMAP 7.1).
3. **알림 채널 인프라 부재**: 재입고 알림·선물하기 공유·정기배송 실패 안내 모두 이메일/푸시 발송이
   필요하다. 최소 "인앱 알림함"으로 시작하고 이메일은 후속 과제로 분리하는 것을 제안한다.
   > ✅ 해소: 인앱 알림함(`Notification`) + 이메일(`EmailSender` — `spring.mail.host` 있으면 SMTP, 없으면 로깅). 웹 푸시(`PushSender` — `push.vapid.private-key` 있으면 실발송, 없으면 로깅).
4. **셀러 참여 범위**: 컬렉션/타임딜을 관리자만 편성할지, 셀러도 신청할 수 있게 할지.
   > 구현: 컬렉션은 관리자 전용, 플래시세일은 셀러 신청 + 관리자 편성.
5. **인센티브 자동 지급 어뷰징 방지 원칙 — ✅ 확정(2026-09-25, "표준 방어")**: 리퍼럴 보상·리뷰 이벤트 등
   행동 기반 자동 쿠폰/포인트 지급 기능은 모두 아래를 공통으로 지킨다.
   - **1인 1회**: 회원 + 연락처 기준으로 같은 보상의 중복 지급을 막는다.
   - **자기추천 차단**: 추천인·피추천인의 연락처 또는 배송지가 같으면 보상하지 않는다.
   - **구매확정 후 지급, 취소·환불 시 회수**: 가입·주문 생성만으로는 지급하지 않고 구매확정(DELIVERED) 시점에 지급,
     이후 취소·환불되면 지급분을 회수한다(포인트는 lot 회수, 쿠폰은 미사용분 회수).
   - **1인 월 지급 상한**: 기능별 상한을 정책 행(DB)으로 두고 관리자가 조정한다.
