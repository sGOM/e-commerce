# 기획전 / 컬렉션 큐레이션

> 우선순위: **P1** (Should)
> 관련 도메인: `catalog`(Product 참조), `admin`(편집 진열), 신규 `promotion`(가칭) 도메인

## 1. 개요 및 배경

마켓컬리는 카테고리 탐색과 별개로 "이번 주 특가", "컬리 단독", "제철 식재료" 같은 편집 진열
컬렉션으로 발견 경험을 만든다. 우리 플랫폼은 현재 카테고리 필터와 인기상품(판매량 기반 자동
랭킹)만 있고, MD/운영자가 수동으로 상품을 골라 노출하는 "편집 진열" 수단이 없다. 카테고리는
분류 체계이고 컬렉션은 마케팅 메시지 중심 묶음이라는 점에서 역할이 다르며, 신규 도메인이지만
기존 Product를 참조하기만 하면 되어 구현 난이도가 낮다.

## 2. 목표 및 성공지표

- 목표: 관리자(또는 향후 셀러)가 상품을 묶어 배너/제목과 함께 노출하고, 고객이 홈/탐색에서
  컬렉션을 통해 상품을 발견한다.
- 성공지표(제안)
  - 컬렉션 노출 대비 클릭률(CTR)
  - 컬렉션 경유 구매 전환율 vs 일반 탐색 대비
  - 활성 컬렉션 수, 컬렉션당 평균 상품 클릭 수

## 3. 유저 스토리 & 수용기준(AC)

### US-1. 관리자는 컬렉션을 생성하고 상품을 편성할 수 있다
- AC1: 제목, 부제, 배너 이미지, 노출기간(startAt~endAt), 상품 목록(순서 포함)을 등록할 수 있다.
- AC2: 컬렉션은 `DRAFT`(작성중) → `PUBLISHED`(노출) → `ENDED`(종료) 상태를 가진다.
- AC3: `PUBLISHED`여도 `endAt`이 지나면 자동으로 고객에게 노출되지 않는다(배치/조회 시점 필터
  중 하나로 처리, 상태값 자체를 강제 전이할지는 오픈 이슈).
- AC4: 상품 순서를 드래그 또는 순번 입력으로 변경할 수 있다.

### US-2. 고객은 진행 중인 컬렉션을 탐색할 수 있다
- AC5: 홈(또는 탐색) 화면에 진행 중(`PUBLISHED` and 기간 내) 컬렉션 목록이 노출된다.
- AC6: 컬렉션 상세 진입 시 편성된 상품 목록을 지정된 순서대로 볼 수 있다.
- AC7: 컬렉션에 담긴 상품 중 판매중지(`HIDDEN`/삭제)된 상품은 고객 화면에서 자동 제외된다(편성은
  유지, 노출만 제외 — 관리자가 다시 켜면 노출도 복구).
- AC8: 품절 상품은 컬렉션에서 제외하지 않고 노출하되 구매 차단(기존 상품 노출 정책과 동일).

### US-3. 관리자는 컬렉션 노출 우선순위를 조정할 수 있다
- AC9: 여러 컬렉션이 동시에 `PUBLISHED`일 때 `displayOrder`로 노출 순서를 정할 수 있다.

## 4. 정책/규칙 & 예외

- **상품 중복 편성**: 같은 상품이 여러 컬렉션에 동시에 속할 수 있다(제약 없음).
- **빈 컬렉션**: 상품이 0개인 컬렉션은 `PUBLISHED` 전환을 막거나, 전환은 허용하되 고객 화면에서
  숨김 처리(오픈 이슈 — 운영 편의상 후자를 제안).
- **기간 검증**: `endAt`은 `startAt` 이후여야 한다(등록 시 검증).
- **셀러 참여**: 이번 범위는 관리자 전용 편성으로 한정한다(§8 Out of scope).

## 5. 데이터 모델 / API 개략 (spring-expert 참고)

```
Collection
  id, title, subtitle, bannerImageUrl
  startAt, endAt, status(DRAFT/PUBLISHED/ENDED), displayOrder
  createdAt/updatedAt

CollectionProduct
  id, collectionId(FK), productId(FK), displayOrder
  unique(collectionId, productId)
```

- 신규 마이그레이션: `collections`, `collection_products`.
- 목록 조회 시 `Product.status`를 조인 필터링(기존 `ProductService.getPopular`의 "집계 후 도메인
  필터" 패턴과 유사하게, 컬렉션 조회도 "편성 순서 유지 + 노출 상태 필터" 조합이 필요).

### API 개략
| 메서드 | 경로 | 설명 | 인증 |
|---|---|---|---|
| GET | `/api/collections` | 진행 중 컬렉션 목록(홈 노출용) | 불필요 |
| GET | `/api/collections/{id}` | 컬렉션 상세 + 상품 목록 | 불필요 |
| POST | `/api/admin/collections` | 컬렉션 생성 | 관리자 |
| PUT | `/api/admin/collections/{id}` | 컬렉션 수정(메타/기간) | 관리자 |
| PATCH | `/api/admin/collections/{id}/status` | 상태 전이(DRAFT→PUBLISHED 등) | 관리자 |
| PUT | `/api/admin/collections/{id}/products` | 상품 편성(목록+순서 일괄 저장) | 관리자 |
| GET | `/api/admin/collections?status=` | 관리자 목록 검색 | 관리자 |

## 6. 프론트 화면/플로우 개략 (react-expert · uiux-expert 참고)

- **홈 진입점**: 현재 스토어프론트는 `ProductListPage`가 사실상 홈 역할로 보인다. 상단에 컬렉션
  가로 캐러셀(배너 카드) 섹션을 추가하고, 클릭 시 컬렉션 상세 라우트(`/collections/:id`)로 이동.
- **컬렉션 상세**: 배너 + 제목/부제 + 상품 그리드(기존 `ProductCard` 재사용).
- **관리자 백오피스**: 컬렉션 목록 테이블(상태 배지 포함) → 편집 화면에서 메타 폼 + 상품 검색/추가
  + 드래그 순서 변경(또는 단순 순번 입력 리스트로 MVP 단순화 가능, react-expert 판단).
- 접근성: 배너 캐러셀은 자동재생 지양(또는 일시정지 컨트롤 제공), 상품 그리드는 기존 카드 패턴을
  그대로 따라 신규 상태색 정의가 필요 없음.

## 7. 기존 기능과의 연계/영향

- **catalog 도메인**: `Product` 조회만 하고 수정하지 않는 읽기 전용 참조. 상품 상태 변경(숨김 등)
  시 컬렉션 쪽 별도 동기화 로직 불필요(조회 시점 필터로 충분).
- **admin 백오피스**: 기존 관리자 메뉴(셀러 심사·쿠폰·정산 등)에 "컬렉션 관리" 메뉴 추가.
- **인기상품과의 차이**: 인기상품은 판매량 자동 집계(편집 불가), 컬렉션은 수동 편성. 두 섹션이
  홈에 함께 노출될 수 있음(IA상 구분 명확히 라벨링 필요 — uiux-expert 검토).

## 8. 범위 (In / Out of scope)

**In scope**
- 관리자 컬렉션 CRUD, 상품 편성/순서, 노출기간, 고객 노출(목록/상세)

**Out of scope**
- 셀러가 직접 컬렉션을 신청/편성하는 플로우(운영 정책 결정 후 후속 검토)
- 개인화 추천 기반 컬렉션(고정 편성만 지원)
- A/B 테스트, 컬렉션별 별도 프로모션가(타임딜과는 별도 기능, 필요 시 연계는 후속 검토)

## 9. 오픈 이슈 (결정 필요)

1. **종료 시점 자동 상태 전이**: `endAt` 경과 시 배치로 `ENDED`로 강제 전이할지, 조회 시점에
   기간만 필터링하고 상태값은 그대로 둘지 — 운영 대시보드 정확성 vs 구현 단순성 트레이드오프.
2. **빈 컬렉션 노출 정책**: 상품 0개 컬렉션을 `PUBLISHED`로 둘 수 있게 할지 여부.
3. **셀러 참여 확대 여부**: 셀러가 자기 상품을 특정 컬렉션에 "신청"하는 구조로 확장할지는 커머스
   운영 리소스(검수 인력) 상황에 달려 있어 이번 단계에서는 보류.
