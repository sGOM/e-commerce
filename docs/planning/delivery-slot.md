# 배송 슬롯 예약 (새벽배송/시간대 지정)

> 우선순위: **P1** (Should, 단 지역 커버리지 등 전제 확정 후)
> 관련 도메인: `order`(SubOrder/Shipment), `catalog`(Product 배송속성), 신규 `delivery`(가칭) 도메인

## 1. 개요 및 배경

마켓컬리의 대표 차별점은 "샛별배송"(마감시간 전 주문 시 다음날 새벽 배송)이다. 배송 예측
가능성 자체가 신뢰 요소다. 우리 플랫폼은 현재 SubOrder 단위로 배송지·송장만 관리하며, "언제
도착하는지"에 대한 약속(슬롯)이 없다. 이 기능은 마켓컬리 차별점의 핵심이지만, **실제 물류
파트너·권역 커버리지·기사 배차 등 오프라인 운영 전제가 정해지지 않으면 시스템만으로는 지킬 수
없는 약속**이 되므로 P1으로 두고, 먼저 데이터 모델과 화면을 정의해 둔다.

## 2. 목표 및 성공지표

- 목표: 고객이 주문 시 배송 시간대(슬롯)를 선택하고, 마감시간(cutoff) 이후에는 다음 슬롯으로
  자동 이월되며, 슬롯 정원을 넘지 않게 관리한다.
- 성공지표(제안)
  - 슬롯 선택 주문 비율(새벽배송 가능 지역 내)
  - 슬롯 정시 배송 준수율(운영 지표, 시스템 밖 물류 KPI와 연동)
  - 슬롯 마감 임박 시 주문 포기율(UX 이탈 지표)

## 3. 유저 스토리 & 수용기준(AC)

### US-1. 관리자는 배송 슬롯을 개설한다
- AC1: 날짜, 시작/종료 시각, 유형(DAWN/DAYTIME 등), 정원(capacity), 주문 마감시각(cutoffAt)을
  등록한다.
- AC2: 슬롯은 특정 지역(권역)에만 적용될 수 있다(전국 공통 슬롯도 가능).

### US-2. 고객은 결제 전 배송 슬롯을 선택한다
- AC3: 새벽배송 가능 상품(`Product.dawnDeliveryEligible = true`)이 포함된 SubOrder에 한해 슬롯
  선택 UI가 노출된다. 일반 배송 상품은 슬롯 없이 기존 방식 그대로 진행 가능.
- AC4: `cutoffAt`이 지난 슬롯은 선택 목록에서 자동 제외되고 다음 가용 슬롯이 기본 노출된다.
- AC5: 배송지가 새벽배송 미지원 권역이면 새벽 슬롯 자체가 노출되지 않는다(일반배송만 가능).
- AC6: 슬롯은 **SubOrder 단위**로 선택한다(멀티셀러 주문 시 판매자별로 슬롯이 다를 수 있음 —
  기존 "배송은 SubOrder 단위" 원칙과 정합).

### US-3. 슬롯 정원을 초과해 예약되지 않는다
- AC7: 슬롯 선택/주문 확정 시 재고 원자적 UPDATE와 동일한 패턴으로 `reservedCount`를 증가시키고,
  정원 초과 시 예약이 거절된다(동시 주문 다발 시에도 초과 예약 0건).
- AC8: 정원이 소진된 슬롯은 즉시 선택 불가로 전환된다(재고 품절과 유사한 UX).

### US-4. 주문이 취소되면 슬롯 정원이 복원된다
- AC9: SubOrder 취소/부분취소 시 해당 슬롯의 `reservedCount`를 복원한다(재고 `release()`와 동일
  원칙).

## 4. 정책/규칙 & 예외

- **판매자별 새벽배송 가능 여부**: 새벽배송은 특정 물류 계약을 맺은 판매자만 지원할 수 있다.
  `Product.dawnDeliveryEligible`은 상품 단위지만, 실제로는 셀러(Store) 단위 계약을 상품에
  상속하는 형태가 현실적이다(오픈 이슈).
- **혼합 주문**: 한 Order에 새벽배송 가능 SubOrder와 불가능 SubOrder가 섞이면, 각 SubOrder가
  독립적으로 슬롯을 선택하거나 일반배송으로 진행된다(기존 SubOrder 단위 배송 원칙 그대로 재사용
  되므로 추가 설계 부담이 낮다).
- **지역 제한**: MVP는 우편번호/행정동 화이트리스트 방식의 단순 매핑 정책 테이블로 시작(정교한
  권역 폴리곤 관리는 범위 밖).
- **추가 배송비**: 새벽배송에 별도 요금을 부과할지는 "공통 오픈 이슈: 배송비 모델 부재"와 직결—
  이 문서에서는 요금 로직을 확정하지 않는다.
- **슬롯 변경/취소**: 주문 확정 후 슬롯 변경은 배송 준비 시작 전(`SubOrder.status = PAID` 단계)
  까지만 허용을 제안.

## 5. 데이터 모델 / API 개략 (spring-expert 참고)

```
DeliverySlot
  id, date, startTime, endTime, type(DAWN/DAYTIME)
  cutoffAt, capacity, reservedCount
  regionScope(nullable, 정책 테이블 참조 또는 문자열 코드)

DeliveryRegion (신규, 단순 화이트리스트)
  id, postalCodePrefix 또는 dongCode, dawnDeliveryAvailable(Boolean)

SubOrder 확장
  deliverySlotId(nullable FK)

Product 확장
  dawnDeliveryEligible(Boolean, default false)
```

- 슬롯 정원 원자적 UPDATE(재고 예약 쿼리와 동일 패턴):
  ```sql
  UPDATE delivery_slots SET reserved_count = reserved_count + 1
   WHERE id = :slotId AND reserved_count < capacity AND cutoff_at > now()
  ```
- 신규 마이그레이션: `delivery_slots`, `delivery_regions`, `sub_orders`/`products` 컬럼 추가.

### API 개략
| 메서드 | 경로 | 설명 | 인증 |
|---|---|---|---|
| GET | `/api/delivery-slots?postalCode=&date=` | 선택 가능 슬롯 목록(마감/정원 필터 적용됨) | 불필요 |
| POST | `/api/orders` 요청에 `deliverySlotId` 필드 추가 | 주문 생성 시 슬롯 예약 포함 | 회원/게스트 |
| GET | `/api/admin/delivery-slots` · `POST` | 슬롯 조회/개설 | 관리자 |
| PATCH | `/api/admin/delivery-regions` | 새벽배송 가능 지역 관리 | 관리자 |

## 6. 프론트 화면/플로우 개략 (react-expert · uiux-expert 참고)

- **체크아웃 화면**: 배송지 입력 직후, 새벽배송 가능 SubOrder가 있으면 슬롯 선택 스텝을 삽입
  (날짜 탭 + 시간대 카드 리스트, 마감임박/마감된 슬롯은 비활성 스타일).
- **주문 상세/마이페이지**: 선택된 슬롯 정보(날짜·시간대)를 배송 정보 영역에 표시.
- **관리자 백오피스**: 슬롯 캘린더 뷰(날짜별 정원/예약률), 지역 화이트리스트 관리 테이블.
- 마감임박 UX: 카운트다운 대신 "OO시까지 주문 시 내일 새벽 도착" 문구형 안내를 우선 제안(카운트다운은
  체크아웃 이탈을 유발할 수 있어 신중히 — uiux-expert 검토).

## 7. 기존 기능과의 연계/영향

- **order 도메인**: `OrderService.buildOrder`에 슬롯 검증/예약 단계 추가. `cancelSubOrder`에 슬롯
  복원 단계 추가(재고 복원과 같은 트랜잭션에서 처리).
- **catalog 도메인**: `Product`에 배송속성 필드 추가(스키마 확장, 기존 조회 API 응답 확장).
- **shipment 도메인**: 기존 `Shipment`(송장) 엔티티와는 별개 — 슬롯은 "배송 시점 약속", Shipment는
  "실제 송장/배송 상태"로 역할이 다르다. 혼동 방지를 위해 명확히 분리해 문서화.

## 8. 범위 (In / Out of scope)

**In scope**
- 슬롯 마스터 관리, SubOrder 단위 슬롯 예약/정원 동시성 제어, 지역 화이트리스트, 마감시각 처리

**Out of scope**
- 실제 배차/기사 운영, 물류 파트너 연동(TMS 등)
- 슬롯별 추가 배송비 부과 로직(배송비 모델 확정 후 별도 기획)
- 실시간 배송 위치 추적

## 9. 오픈 이슈 (결정 필요) — 다른 기능 대비 특히 많음, 착수 전 우선 확정 권장

1. **물류 운영 주체**: 자체 배송망인지 외부 3PL 연동인지에 따라 슬롯 정원의 의미(시스템상 숫자
   vs 실제 배차 가능량 동기화)가 크게 달라진다.
2. **새벽배송 자격의 단위**: 상품 단위 vs 셀러(Store) 단위 — 실무적으로는 셀러 계약 단위가
   합리적이나, 문서에서는 상품 필드로 초안했다. 확정 필요.
3. **지역 판정 방식**: 우편번호 접두사 화이트리스트로 충분한지, 더 정교한 권역 관리가 필요한지.
4. **배송비/추가요금 정책**: 공통 오픈 이슈와 연동, 새벽배송 프리미엄 요금 여부.
5. **슬롯과 Shipment 상태 전이 연계**: 슬롯 시간이 지나도 실제 배송완료 처리(Shipment)는 판매자가
   수동으로 하는데, 이 둘 사이 불일치(슬롯 시간은 지났는데 미배송)를 어떻게 노출/알림할지.
