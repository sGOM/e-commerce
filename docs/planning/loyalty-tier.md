# 누적구매 로열티 등급 (Loyalty Tier)

> 우선순위: **P1(신규)** — [wishlist-price-alert.md](./wishlist-price-alert.md) §0 브레인스토밍 #3
> 작성일: 2026-07-05 / 작성자: 프로덕트 기획(planner)
> 상태: ✅ 구현 완료(2026-07-05). 확정 정책은 오너 결정 반영본.
> 관련 도메인: 신규 `loyalty`, `order`(순구매액 집계), `coupon`(승급 쿠폰, 기존 재사용), `membership`(개념 분리)

## 1. 배경 / 문제 정의

단골·핵심 고객을 식별하고 보상하는 장치가 없었다. 유료 멤버십(`membership`)은 "돈 내고 가입하는"
구독이라, **결제 이력만으로 자연 형성되는 충성도**를 보상하지는 못한다. 누적 구매가 많은 고객에게
등급과 혜택을 주어 **장기 록인·객단가·구매빈도**를 끌어올린다.

## 2. 목표 및 성공지표
- 목표: 최근 구매 실적 기준으로 고객을 등급화하고, 상위 등급에 실질 혜택(쿠폰)을 제공해 재구매를 유도.
- 성공지표(제안): 등급별 재구매율·객단가, 상위 등급 유지율, 승급 쿠폰 사용률, 등급 상승이 구매빈도에 미치는 영향.

## 3. 핵심 유저 스토리 & 수용기준(AC)

**US-1. 고객은 내 등급과 다음 등급까지 남은 금액을 본다.**
- AC1: 마이페이지 "내 등급"에서 현재 등급, 최근 12개월 순구매액, 다음 등급까지 남은 금액, 산정 시각을 본다.
- AC2: 등급은 BRONZE/SILVER/GOLD/VIP 4단계이며 시각적으로 구분(뱃지 색)된다.

**US-2. 구매가 쌓이면 자동으로 승급하고 혜택을 받는다.**
- AC3: 최근 12개월 순구매액(실결제액, 취소/환불 제외)이 임계값을 넘으면 다음 등급으로 승급한다.
- AC4: 승급 시 해당 등급 전용 쿠폰이 **자동 발급**된다(쿠폰함에 노출). 같은 등급 재승급 감지 시 중복 발급되지 않는다.
- AC5: 최근 12개월 실적이 임계 아래로 내려가면 **강등**된다(강등 시 쿠폰 회수는 하지 않음).

**US-3. 관리자는 등급 현황을 조회·재계산한다.**
- AC6: 관리자는 등급별 회원 목록을 조회하고, 등급 재계산 배치를 수동 트리거할 수 있다.

## 4. 정책/규칙 (확정)

- **산정 기준**: 최근 12개월 **순구매액**(롤링 윈도우). 유효 상태(`PAID/PREPARING/SHIPPED/DELIVERED`)만
  합산, `CREATED/CANCELED`(미결제·취소)는 제외 → "실결제, 취소/환불 제외".
- **임계값(확정)**: SILVER 30만 / GOLD 100만 / VIP 300만 원. `@ConfigurationProperties(loyalty)`로
  분리해 배포 없이 조정 가능(실 데이터 축적 후 재조정 여지).
- **혜택 = 등급 승급 쿠폰 자동 발급 (오너 확정)**: 무료배송 등 다른 혜택은 out of scope.
  - **포인트 적립 배수는 유료 멤버십 전용**으로 두어 로열티와 개념 충돌을 없앤다(핵심 결정).
  - 등급↔쿠폰 매핑은 `loyalty-coupon.couponIdByTier` 설정. 관리자가 등급별 `Coupon`을 먼저 만들고
    id를 등록해야 실제 발급(미등록 시 조용히 미발급 — 안전한 기본값).
- **재계산**: 일 1회 배치(기본 비활성, 관리자 수동 트리거 병행). 승급/강등 모두 반영.
- **다단계 승급**: BRONZE→GOLD처럼 여러 단계 건너뛰면 **최종 도달 등급 쿠폰만** 발급(중간 등급 미발급).
- **멱등성**: `existsByCouponIdAndUserId`로 이미 받은 등급 쿠폰이면 건너뜀. 쿠폰 발급 실패는 등급
  갱신과 별도 트랜잭션으로 격리(배치 전체를 중단시키지 않음).

## 5. 데이터 모델 / API (구현 결과)

```
LoyaltyTierProfile  (회원당 1행)
  userId(FK), tier(BRONZE/SILVER/GOLD/VIP), netPurchaseAmount, calculatedAt
LoyaltyCouponProperties: loyalty-coupon.couponIdByTier = { SILVER: n, GOLD: n, VIP: n }
쿠폰: 기존 Coupon/IssuedCoupon 재사용(스키마 변경 없음)
```
마이그레이션: **V24__loyalty_tier.sql** (`loyalty_tier_profiles` 1개 테이블).

| 메서드 | 경로 | 설명 | 인증 |
|---|---|---|---|
| GET | `/api/me/loyalty-tier` | 내 등급·다음 등급까지 남은 금액 | 회원 |
| GET | `/api/admin/loyalty-tiers?tier=&page=` | 등급별 회원 목록 | 관리자 |
| GET | `/api/admin/loyalty-tiers/{userId}` | 회원 등급 상세 | 관리자 |
| POST | `/api/admin/loyalty-tiers/recalculate/run` | 등급 재계산 배치(수동) | 관리자 |

## 6. 프론트 화면
- 마이페이지 "내 등급" 카드: 등급 뱃지·순구매액·다음 등급 진행바·산정 시각·"등급 전용 쿠폰" 안내.
- 관리자: 등급 목록 + 등급 필터 + 수동 재계산 버튼.

## 7. 범위 (In / Out of scope)
**In**: 등급 산정(12개월 순구매액)·승급/강등·승급 쿠폰 자동발급·조회/재계산.
**Out**: 등급별 무료배송 등 쿠폰 외 혜택(배송비 모델 선행), 생일 쿠폰, 등급 유지 조건 세분화, 강등 시 쿠폰 회수.

## 8. 오픈 이슈
1. 임계값(30만/100만/300만)은 오너 확정값이나 실 결제 데이터 축적 후 재조정 대상.
2. 등급별 쿠폰 정의를 관리자가 먼저 생성·매핑해야 실동작(운영 온보딩 필요).
3. 다단계 승급 시 중간 등급 쿠폰 미발급 정책 — 필요 시 재검토.
